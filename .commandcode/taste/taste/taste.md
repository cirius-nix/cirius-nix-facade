# Taste
- Manages a personal dotfiles/NixOS configuration as a Nix flake (repo `~/.personal/dotfiles/cirius-nix-facade`), composing NixOS, home-manager, sops-nix (for secrets), and devenv (for dev shells) modules. Confidence: 0.6
- Structures the config as a facade flake with per-concern subflakes under `flakes/<name>/` (e.g. `cirius-security`) wired together, with modules generated/discovered by snowfall-lib's `mkFlake` from `modules/{home,nixos,darwin}/<name>/default.nix`. Confidence: 0.55
- Debugs Nix evaluation errors with `nix repl`, loading flakes via the `:lf <path>` command and evaluating attributes directly (e.g. `outputs.nixosConfigurations.<host>.config`) rather than full builds. Confidence: 0.55
- Expects full traces when diagnosing Nix errors, running with `--show-trace`. Confidence: 0.5
- Prefers fixing root causes permanently in the Nix config (flake wrapper/env changes, then rebuild) over one-off manual workarounds that leave the underlying problem in place. Confidence: 0.4
- Places site/app projects under an `apps/<name>/` directory in the repo (monorepo convention) rather than at the repo root. Confidence: 0.55
- Hosts static sites on GitHub Pages and auto-deploys them via GitHub Actions on push. Confidence: 0.6
- Prefers the latest version of a framework/tool (e.g. asked for Docusaurus "latest"). Confidence: 0.5
- Frames his NixOS config as a way to reduce the setup and complexity of managing Linux infrastructure-as-code: it should manage only the core, valuable settings that keep Linux running well, "simple by default, powerful when needed". Confidence: 0.7
- Wants documentation for each flake/module plus a config reference covering every option's type, default, and capability, with the option data extracted from the actual `.nix` sources rather than written from memory. Confidence: 0.7
- Prefers per-flake doc pages that present module narrative and full option tables together, kept accurate by hand rather than generated by a script or a Nix evaluation at build time. Confidence: 0.55
- Tends to reject optional code-generation/drift-mitigation infrastructure in favor of hand-maintained docs. Confidence: 0.5
- Runs fcitx as his input method (its `ctrl+space` toggle is non-negotiable) and catches keybinding collisions with it — new tools' keys must be chosen to avoid clashing with his existing terminal shortcuts (`ctrl+a`) and the IME toggle, falling back to upstream defaults like tmux's `ctrl+b` when in doubt. Confidence: 0.6
- When configuring a new tool, prioritizes "easiest to use" and wants it to mirror the settings/keybindings/theme of his existing tool of the same class (e.g. herdr configured to feel like his Ghostty setup) rather than accept upstream defaults. Confidence: 0.55
